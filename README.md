# NekoTab

[![CI](https://github.com/remloyal/NekoTab/actions/workflows/ci.yml/badge.svg)](https://github.com/remloyal/NekoTab/actions/workflows/ci.yml)

极简、可自部署的书签导航页，界面参照浏览器新标签页：大字时钟（带农历）+
搜索引擎框 + 分类标签页 + 图标网格。

用 [Dioxus 0.7](https://dioxuslabs.com/) fullstack 写成：同一份 Rust 代码编译出
服务端（Axum + SSR）和浏览器端（WASM + Hydration），数据存单文件 SQLite。

## 功能

**首页**

- **时钟**：实时时钟 + 日期，可另开农历（如「二〇二六年九月初四」）与
  「第 N 天 · 第 N 周」，都可在设置里关掉；还能切 12 小时制（带「上午 / 下午」）
  和隐藏秒。
- **一言**：时钟下方一句「一言」，默认每 5 分钟换一条。服务端代取接口，
  失败时保留上一条，不显示错误、不打断页面。
- **搜索框（两种用途）**：右侧按钮在「网页 / 书签」之间切换。
  - **网页**：左侧选搜索引擎，回车或点 `→` **在新标签页**搜索，当前书签页不受影响。
    输入时会带出该引擎的**联想词列表**（点一下或回车即用它去搜）：`↑` `↓` 选、
    `Enter` 确认、`Esc` 收起。
  - **书签**：输入即筛下方卡片（同时匹配名称、网址、描述，以及导入时留下的文件夹
    路径），回车不跳转。这个模式不出联想面板——下方网格本身就在实时筛。
- **引擎前缀**：给某个引擎配了前缀后，输入「前缀 + 空格 + 关键词」即可临时改用它，
  例如给 GitHub 配 `gh`，输入 `gh rust` 就用 GitHub 搜 rust。前缀必须独立成段，
  所以输入 `github` 不会被误当成前缀 `gh`。
- **搜索引擎可编辑**：引擎设置里每张卡片都有「编辑」，名称 / 地址 / 图标 / 前缀都能改，
  不必删了重建；上方还有一排**常用引擎**（百度 / 必应 / Google / 搜狗 / 360 / 开发者搜索 /
  B站 / 微博 / DuckDuckGo），点一下即添加，已有的会标出来。
- **分类标签页**：由**分组**驱动（`全部 12` / `未分组 3` / `开发 5`），点选即筛选；
  分组始终显示，新建的空分组标 `0` 条、点进去是空态（不会"建完就消失"）。
  标签页条数跟随当前结果集变化。
  一条书签可以同时属于**多个分组**，于是它会出现在多个标签页下；「全部」的条数
  仍按书签数算，不会重复计数。首页只有这一个分类入口，见下方「分类只由分组承担」。
- **添加卡片**：点网格末尾的 ＋，或在**空白处右键 → 添加卡片**，都会打开同一个
  弹窗——里面用标签页分「网址导航」和「小组件」两类（右键菜单里直接点某一项，
  会打开弹窗并停到对应那一页）。
  网址已在列表里（**回收站里的也算**）时不会重复写入，弹窗会直接说明原因。
- **打开**：点图标打开对应网址；开新标签页还是当前页由设置决定。
- **站点图标**：卡片上自动显示对应站点的真实图标（服务端代取并缓存到磁盘）；
  取不到时回退成「名称首字 + 哈希取色」的彩色块。想自己定也可以——表单里的图标
  选择器给了四种：**自动**（按网址取站点图标）、**内置图标**（23 个自绘线框图）、
  **文字**（一两个字 + 底色）、**自定义地址**（任意图片直链或 `/...` 本地路径）。

**整理书签**

- **卡片编辑态**：**长按卡片**（按住约 0.5 秒）进入编辑态——卡片显示 ✕ 删除角标与
  拖拽手柄，底部出现操作栏。此时：
  - **拖动**卡片调整顺序（鼠标与触屏都支持，落位后写回数据库）；
    书签分页时，把卡片拖到分页条的上一页 / 下一页按钮上会**自动翻页**，
    松手即落在目标页上（跨页拖动）；
  - **点卡片**打开修改弹窗（名称 / 网址 / 描述 / 分组 / 图标，字段预填）；
  - **点 ✕** 二次确认后删除（进回收站，可还原）。
- **批量操作**：编辑态点「批量选择」进入选择模式——点卡片切换选中，
  底栏可**移到分组**、**批量删除**（都进回收站），另有「全选本页」。
- **右键菜单**：卡片上可打开 / 编辑 / **移到分组** / 批量选择（从这条开始）/ 删除；
  空白处可添加卡片 / 刷新列表。
- **回收站**：删除是软删除，书签先落在设置里的回收站，可逐条还原或彻底删除、
  也可以一次清空。
- **分组管理**：设置里增删改分组、**从内置图标里挑一个**（或填图片地址）、
  用 ↑ ↓ 调整标签页顺序；图标会显示在首页的分类标签页上。
  删除分组不会删书签，只会把它从书签的归属里移除；没有其它分组的书签落到「未分组」。
- **分页**：书签多了可以在设置里设「每页卡片数」，用圆点、翻页按钮、
  `←` `→`、`PageUp` `PageDown`、鼠标滚轮（可选）或触屏左右滑动翻页，
  还能开循环翻页。

**外观**

- **主题**：深色 / 浅色两套，配色走 CSS 变量；也能选**跟随系统**，随操作系统的
  深浅色偏好切换（系统切换时页面即时跟随）。
- **内置壁纸**：6 套纯 CSS 渐变（极光 / 星云 / 森林 / 海洋 / 晚霞 / 素墨），
  深色浅色各一套配色，不依赖外网。
- **背景池**：能用的背景收在一个池子里——**图片直链**（含随机图接口）与**上传到
  服务器的图**混在一起，点缩略图即设为当前背景。开着「每次打开换一张」时每次都从
  池里随机挑一张；池里只有一张时改为给地址追加随机参数，绕开图片接口的长缓存。
  这一节的改动**即时生效**（传完图就是背景，不用再点一次保存）。
- **存到本地**：外链条目一键抓回自己服务器（落在 `WALLPAPER_DIR`，单张上限 16 MB，
  失败会说明原因），之后不再依赖对方站点——防盗链、限流、图床关站都与它无关。
- **上传单张上限 16 MB**，选文件时就在前端查大小：超了当场告诉你"哪张、多大"，
  不会白传一遍再被服务端拒掉。
- **本机文件兜底条带**：`WALLPAPER_DIR` 里有、但不在池里的图（旧版本上传的、手动
  丢进目录的、被你自己移出池的）会折叠成一行，可加回池或删除；壁纸不参与任何自动
  清理，所以不能让它们从界面上消失。面板同时显示本机壁纸的张数与总占用。
- **卡片与布局**：卡片宽度、横向 / 纵向间距、每行**最大**列数（0 为不限）都可调，
  设置里带实时预览。列数只封顶、不写死——窗口变窄放不下时自动换行，不会横向溢出。
- **格子尺寸**：每条书签可以设成占多格（**1×1 / 2×1 / 1×2 / 2×2 / 1×3 / 2×3**，
  在书签表单里选），网格因此从等宽图标阵列变成可以拼版的版面——少数几条做成大卡片，
  其余保持一格。行高固定成一格，卡片一律对齐到格子上；图标按格子的短边等比放大，
  所以 1×1 与以前完全一样。窄到放不下时宽度那一维会自动收回一格，
  保证卡片仍落在整数格上。
  > 跨格只改排版：顺序、分页、拖拽、批量选择一律不受影响（网格不做 dense 回填，
  > 代价是同一行可能留洞）。这一层也是大格子里放内容的容器，见下面的「组件」。
- **组件**：大格子里不只能放书签，还能放组件——在「添加卡片」弹窗的**小组件**页里挑一种。
  现有七种：

  - **数字时钟**：可调 12 / 24 小时制与是否显示秒；矮格子里自动收起日期那一行。
  - **表盘时钟**：SVG 画的指针表盘，可开关秒针与数字刻度（关掉数字就是 12 条短线）。
  - **日历**：当月月历，可前后翻月、标出今天；可显示今天的农历、切换一周从周一还是周日开始。
  - **待办**：卡片上直接勾选，显示「已完成 / 总数」；条目在组件设置里一行一条地编辑，
    行首写 `[x]` 表示已完成。
  - **记事本**：写待办与备忘，换行照原样保留，最多 2000 字（按字符截断）。卡面是只读的
    展示面，**点卡片直接打开它的编辑器**；空笔记显示「点一下写点什么」。
  - **天气**：填一个地名（如「北京」），气温、天气与今日高低；可切华氏度。
    数据源是 **Open-Meteo**，不需要密钥（见「已知限制」）。
  - **热搜**：百度 / 知乎 / B站 / 微博 / 头条五选一，服务端代取并缓存十分钟；
    点条目开新标签页。

  组件占多格（默认 2×2），显示在网格最前，**不参与**关键词筛选、分组计数与分页，
  拖拽也只在同类之间生效；卡片内容按格子尺寸自适应（字号同时受格子的宽和高约束，
  表盘按格子的短边等比缩放）。同一种组件只留一个，再点它是它的设置。
  组件与书签共用同一套表格、顺序与拖拽，见「已知限制」里那条说明。
- **卡片底色**：组件卡默认带一层**半透明**的底（带背景模糊）——它的内容是文字与细线，
  直接压在花哨壁纸上会看不清；书签卡默认仍是**透明**的（内容是"彩色图标块 + 一行短标题"，
  图标块自带底色与投影，这是各家新标签页的共同做法）。每张卡片（书签或组件）都可以单独选
  **默认 / 无 / 半透明 / 实底**。
  底色与字色是**成套**的：深色主题深底浅字、浅色主题白底深字，跟着主题切换，
  不需要自己配色。组件卡下面还有一行名字——几张组件摆一起时，光看内容不好认。
- **文字图标**：图标除了自动代取、内置图标、图片地址，还能用一两个字 + 底色拼一块
  彩色图标；分组和书签共用同一个图标选择器。
- **站点信息**：设置 → 站点信息里可改浏览器标签页标题、描述、关键词、站点图标与
  移动端主题色，不必改代码重编译；同一节也放了「退出登录」。
- **简约模式**：只留壁纸、时钟和搜索框，把网格整个隐藏。

**数据**

- **导入**：设置里可直接**选文件**（浏览器导出的书签 HTML 或本应用 JSON 备份），
  也可以把内容粘贴进文本框。按 URL 自动去重；**浏览器里的文件夹会变成分组**，
  JSON 备份里的分组按名字还原（分组不存在则自动创建）。浏览器导出文件里带的
  图标（`ICON="data:image/…"`）也会一并收下，落到图标缓存里直接可用。
- **导出**：一键下载无损 JSON 备份（含分组与顺序），能原样搬回来；
  另有 `/export/bookmarks.html`（Netscape 格式，可直接导回浏览器）与
  `/export/db.sqlite`（数据库快照，`VACUUM INTO` 出来的干净单文件）。
- **快捷添加**：设置 → 快捷添加里有一条带令牌的**书签小工具**，拖到浏览器书签栏后，
  在任意网页点一下就把当前页收进来，不必先回到 NekoTab。另有一个
  `POST /api/bookmark` 的 JSON 入口给脚本 / 浏览器扩展用。令牌等同写入权限，
  可在同一处重新生成（旧小工具随之失效）。

**键盘**

- `Ctrl/Cmd + K`：焦点回到搜索框
- `Esc`：按层级依次关闭右键菜单 → 弹窗 → 设置抽屉 → 批量选择 / 编辑态
- `←` `→` `PageUp` `PageDown`：翻页（焦点在有内容的输入框里时让路给光标）

## 技术栈

| 层 | 选型 |
|----|------|
| 全栈框架 | Dioxus 0.7.10（`fullstack` + `router`） |
| 服务端 | Axum 0.8（由 `dioxus::serve` 托管） |
| 数据库 | SQLite + sqlx 0.9（异步连接池，WAL） |
| 序列化 | serde / serde_json |
| 配置 | dotenvy |
| 一言（仅 server） | reqwest（复用 dioxus 已有的 rustls，无系统 OpenSSL 依赖） |
| 响应压缩（仅 server） | tower-http（gzip + brotli） |
| 访问密码（仅 server） | ring（HMAC-SHA256，复用 rustls 已编进来的那份） |
| 时钟 / 农历 / 搜索跳转 / 指针拖拽 / 文件读取（仅 web） | js-sys、gloo-timers、web-sys、wasm-bindgen |

**没有第三方日期库。** 农历是「一张 1900–2100 年的编码表 + 几十行算术」，
自己写在 `src/lunar.rs` 里，配套单测拿历年春节（正月初一）的公历日期校验——
表里任何一格抄错都会让某一年的正月初一对不上，所以这组测试是有效护栏。

## 关键设计

**Feature 隔离。** 依赖按编译目标切开，`sqlx` / `tokio` / `dotenvy` / `reqwest` /
`tower-http` 只在 `server` 下启用，`js-sys` / `gloo-timers` / `web-sys` /
`wasm-bindgen` 只在 `web` 下启用：

```toml
[features]
default = []
web    = ["dioxus/web", "dep:gloo-timers", "dep:js-sys", "dep:wasm-bindgen", "dep:web-sys"]
server = ["dioxus/server", "dep:sqlx", "dep:tokio", "dep:dotenvy", "dep:anyhow", "dep:reqwest", "dep:tower-http"]
```

WASM 产物里不含数据库驱动与 HTTP 客户端；服务端二进制里不含浏览器 JS 绑定。

**连接池初始化。** 建池是异步的，而 `OnceLock::get_or_init` 只接受同步闭包，
所以在 `main` 里先 `await db::init_pool(...)`，再 `set` 进 `OnceLock`。建池时
开 `create_if_missing`、`journal_mode = WAL`，并执行 `sqlx::migrate!` 跑迁移；
同时会补建数据库文件与图标目录的父目录。

**分类只由分组承担。** 早期版本的分类标签页由书签的 `tags` 去重派生，代价是无法
给分类排序、配图标，且一条书签带多个标签就会在多个标签页里重复出现。于是改成显式的
`groups` 表：一条书签归属至多一个分组（`NULL` 即「未分组」，不占一行、由前端合成）。

**标签从此退出界面。** 中途一度把标签作为"第二个筛选维度"加回首页（分组下面一行
标签 chip），并给了表单一个标签选择器；实机一看就是"两排分组"，用户直接问
"为啥需要加个标签分类"。回头看，这正是当初重构掉的东西——**分类入口只能有一个**，
多一个就会让人问"这俩有什么区别、我该用哪个"。所以标签的界面全部撤掉：首页那一行、
表单里的标签字段、批量打标签、`tag_bookmarks` 接口都不再存在。

数据库那一列**保留不动**（列是迁移加的，删列要新迁移，而迁移一旦部署就不能改；
更要紧的是不能悄悄丢数据）。导入仍然把文件夹路径写进它，搜索也仍然匹配它——
`工作/项目A` 里的 `项目A` 因此还是搜得到，只是没有地方显示"标签"这个概念了。

分组的删除是「归位」而非级联：`delete_group` 在同一个事务里把组内书签的
`group_id` 清空，书签本身不动。读列表时前端还会把「指向已不存在的分组」当作
未分组处理，兜住并发删除这类边角——否则那条书签在任何分类下都看不见。

**列表恒为全量，筛选与分页都在客户端。** 书签列表始终取全部
（`list_bookmarks("")`），分类筛选、关键词筛选、分页都只影响**显示**。
这样拖拽重排永远作用在完整顺序上。服务端那套按关键词的 AND/OR 模糊搜索仍然
保留（`POST /api/list_bookmarks` 传 `{"query":"..."}` 即可用），客户端为
「输入即筛」把它搬到了本地，两边口径一致。

**拖拽排序：把视图内的新顺序合并回全量顺序。** 分页和筛选让「看见的」变成全量的
一个子集，直接按视图下标写 `sort_order` 就会把别的书签挤乱。所以落位时用
`move_to_position(全量, 被拖的 id, 落点 id)`：它先算出目标在**全量**里的下标，
把被拖项从原位置摘掉再插进去，写回服务端的始终是**完整顺序**。这个函数还会校验
两个 id 确实在全量列表里，不满足就返回 `None` 整个放弃——排序是低频操作，
多一次比较换来「任何输入都不会把顺序弄乱」。同一个函数顺带把跨页拖拽变成免费的：
落点在第二页的卡片上时，目标下标本来就是全量的下标，不需要为跨页写任何特例。

**跨页拖拽靠分页按钮当落点。** 拖动过程中指针经过上一页 / 下一页按钮时自动翻页，
所以那两个按钮带 `data-page-flip="prev"|"next"` 标记，指针移动时先做一次属性命中
测试（`data_attr_at`），命中就翻页并带 700ms 节流，避免一掠而过翻好几页；
没命中再去找卡片。翻页后用 `elementFromPoint` 也能命中新页的卡片，
于是落位自然正确。

**拖拽走 Pointer Events，鼠标与触屏同一条路径。** 原生 HTML5 拖放在触屏上不触发，
而且 `<a>` 的默认拖拽会把链接地址当拖拽数据，两者会打架。所以按下时尽力把指针
捕获到卡片上（拖出网格也能继续跟踪），**判定与落点计算则放在网格这一层**——
网格是所有卡片的公共祖先，指针捕获失败时移动事件仍会从下方的元素冒泡上来，
拖拽不会因此失效。落点用 `document.elementFromPoint` 做命中测试，
比逐个读卡片矩形便宜。位移超过 8px 才算拖动，抬手后那一次 `click` 会被吞掉，
不会顺手弹出修改弹窗。

**长按与拖拽共用按下事件。** 普通态按下 500ms 且期间位移不超过 8px 才进入编辑态；
编辑态按下则直接进入待拖拽状态。触屏上编辑态的卡片带 `touch-action: none`，
否则拖拽会被浏览器当成滚动手势。

**删除是软删除。** `deleted_at` 置时间戳，列表查询一直带
`deleted_at IS NULL`，所以回收站里见到的是「删了但还在库里」的那些；
只有「彻底删除」才真的 `DELETE`。误删的代价从「不可恢复」变成「点两下还原」。

**站点图标落盘，库里只留元数据。** 图标字节写在 `ICON_DIR`
（默认 `data/icon`）下的独立文件里，`favicons` 表只存
`content_type` / `file_name` / `fetched_at`。这是有意的：几十 KB 一张的图标
塞进 SQLite 会让 `mtab.db` 迅速膨胀，备份、WAL 和 `VACUUM` 都跟着变重，
而图标本来就是可重取的缓存。写盘用「先写 `.tmp` 再改名」，避免半个文件被当成
图标读走并缓存。

**文件名不含域名。** `ls data/icon` 不该把收藏了哪些站点暴露出来，所以落盘名是
「时间戳 + 序号 + 主机名」混出的哈希加扩展名（如 `928615185a1c….ico`）；
同一主机的文件名记在 `favicons.file_name` 里，重复请求命中缓存不会再生成。

取图顺序：`/favicon.ico` → 首页声明的 `<link rel="icon">` → `/apple-touch-icon.png`。
每一步都必须校验 `Content-Type` 是 `image/`——实测 `claude.ai` 对任意路径都返回
`200 + text/html`，不校验就会把整个网页当成图标存下来。声明里**内联的 `data:`
URI 也支持**（现代站点与 SPA 模板常这么写，早先直接跳过等于白丢一类图标），
base64 与百分号编码两种都认。

**取不到图标必须回退成首字色块，而这里有个 hydration 时序坑。** 卡片是"彩色首字
打底、站点图标用 `<img>` 盖在上面，图标的白色底盘正好挡住首字"（底盘是必要的：
很多图标是透明底的浅色设计，直接压彩色渐变会看不见）。取不到时靠 `onerror` 把
`<img>` 撤掉、露出首字——**但这件事光靠 `onerror` 会漏**：`error` 事件不冒泡，
而图标请求是 SSR 那段 HTML 里就开始的，同源 `/icon/{host}` 返回 404 往往比 wasm
下载还快；等 hydration 把 `onerror` 挂上去，事件早发完了。于是那些卡片会一直顶着
浏览器的"碎图"占位符（它还把首字盖住了），看起来就像"图标全挂了"。
所以 hydration 之后由网格补查一次 `naturalWidth`（`dom::mark_broken_favicons`），
给已经失败的 `<img>` 打上 `data-broken`、交给 CSS 隐藏。两条路各管一段：
补查负责"挂监听之前就失败的"，`onerror` 负责"之后才失败的"（以及后来才新增的卡片，
它们的监听是创建时就挂好的）。

这个接口**只服务本站已收藏的站点**：要探测就得先加书签，顺带把这个按 host
代取的接口被当成任意出站探测（SSRF）入口的风险压掉了。设置 `ACCESS_PASSWORD`
后它与其他数据入口一样需要登录。取不到时写一条空数据的负缓存，
**有效期 6 小时**——早先设的是 7 天，但一次瞬时失败（容器刚起、DNS 还没就绪、
对方站点抖一下）就会把图标钉死很久，界面上看起来就是"图标全挂了"。取不到时
还会往服务端日志打一行**逐步原因**（如
`取不到图标 x.com：favicon.ico: 不是图片（text/html）；首页未声明任何图标；apple-touch-icon.png: HTTP 404`），
设置里也有「清空图标缓存」可以立刻全部重新代取。

**搜索提交必须走 JS，不能用原生表单。** 最初的做法是
`<form method="GET" action="{引擎地址，%s 已替换}">`，指望浏览器直接导航过去。
**这是错的**：按 HTML 规范，表单 GET 提交会**替换** action URL 里原有的查询串，
于是搜索词被清空，实测拿到的是 `https://www.baidu.com/s?`（查询词没了）。
而且各引擎参数名不同（百度 `wd`、谷歌 `q`、必应 `q`），还有把词放在路径里的
模板，原生表单无法通用地表达。所以改为拦掉原生提交、由 JS 精确打开那个 URL。
`window.open` 由用户手势（点击 / 回车）触发，不会被弹窗拦截；表单上仍保留
`action` / `target` 作为「JS 没跑起来」时的静态兜底。

**引擎存在数据库里。** `engines` 表带 `active` 标记与 `prefix` 前缀。
前缀在服务端会被规范化为「小写 + 只留字母数字与连字符」，并拒绝与其他引擎重复；
前端只在「前缀独立成段且后面还有关键词」时才认它，避免把 `github` 拆成 `gh` + `ithub`。

**一言由服务端代取。** 浏览器不直接访问 `v1.hitokoto.cn`，而是调用自己的
`get_quote` server function，由服务端发请求。这样避开跨域、统一做 8 秒超时；
失败时前端保留上一条。`reqwest::Client` 用 `OnceLock` 复用，避免每次请求重做
TLS 握手。

**搜索联想只认已知引擎。** 输入时列出当前引擎给的联想词，点一下或回车即用它去搜。

有两个绕不开的约束，都落在设计里：

* **必须服务端代取。** 浏览器的 suggest 接口普遍不带 CORS 头，前端直连拿不到响应。
* **端点只按引擎 id 反查，绝不接受客户端传地址。** 各家联想接口的格式互不相同
  （百度 `{"g":[{"q":…}]}`、必应 `["词",[…]]`、360 `{"result":[{"word":…}]}`、搜狗是
  一段 JSONP），没法像搜索地址那样用一个 `%s` 模板通吃，所以是一张写死的表。如果
  让客户端传 URL 进来，这个后端代取接口立刻变成任意出站请求的入口（SSRF），和
  `/icon/{host}` 只服务已收藏站点是同一个取舍。

**联想的防抖与"过期响应丢弃"。** 每敲一个字就发一次请求太吵，所以停 180ms 才发；
但更麻烦的是**响应回来的顺序不保证**——按"a"和"ab"各发一次，可能"a"的结果后到、
把"ab"的结果盖掉。所以每次输入给一个递增令牌，回来的响应若发现令牌已经变了就丢掉。
引擎请求单独设 2.5 秒超时（比通用那 8 秒短）：联想要跟着手速走，慢就该当作"这家
没有联想"，而不是让面板悬在那里。失败一律返回空表、不报错——联想只是锦上添花，
出口抖一下、对方限流一次，都不该在界面上留下痕迹。

**时钟与农历的 SSR 一致性。** SSR 阶段无从得知「现在」，因此时钟首屏渲染空串，
挂载后由 `use_future` 每秒刷新。服务端与客户端首次渲染结果一致，不会 hydration
失配。农历、第几天、第几周都是纯计算，跟着每秒刷新一起算，不发任何请求。

**主题与背景分成两层。** 主题只换 CSS 变量（`[data-theme="light"]` 里重定义
一批变量），组件规则一行都不用改。背景分两个绝对定位层：底衬层（默认渐变或
内置预设，由 CSS 类决定）与壁纸层（内联 `background-image`）。这么分是因为
dioxus 的解释器在把 `style` 设成空串时，会把「之前设过、现在没了」的内联属性
**补回来**——于是「清空背景图」要刷新才生效；壁纸层改成始终显式写
`background-image: none` 或 `url(...)`，属性一直有值，就没有可补的东西。
两层分开则让「内联图片」和「CSS 渐变」不会互相覆盖。

**背景轮换在客户端算，且哪儿都不存东西。** 池里的选择发生在首页：拿"每次打开"的
时间戳（本来就为绕图片缓存生成的那个 nonce）散列出下标。随机源只在客户端存在，
所以轮换开启时背景要等 hydration 之后才出现——与 v1.6 随机图那套是同一个取舍。
**选中的那条既不回写设置、也不写 `localStorage`**：前者会让每个新标签页都写一次库、
多标签还会互相覆盖，后者是新标签页不该往浏览器里留的东西。代价有两个，都写在设置
的说明文案里——设置里高亮的那张在轮换开启时只是"默认张"；池里只有两张时有 1/2 的
概率连着两次给同一张。另外随机参数只追加到外链地址上——本机的 `/wallpaper/xxx`
内容不会变、响应本来就带 `immutable` 长缓存，追加只是白下一次请求（这是对 v1.6
行为的一处小修正）。

**快捷键要挂在可聚焦的节点上，首屏还得主动送焦点进去。** 键盘事件靠焦点冒泡，
所以根节点带 `tabindex="0"`。但页面加载完成后 `document.activeElement` 是
`<body>`，而 body 不在根节点子树里——挂在根上的 `Esc` / `Ctrl+K` / 翻页键
一个都收不到。所以挂载后主动把焦点送进搜索框（只在焦点确实无处可去时）。
另外「方向键翻页」只在焦点位于**有内容的**输入框时才让路：搜索框默认聚焦，
若只按标签名判断，翻页键就永远用不上，而空输入框里本来也没有光标可移。

**设置是键值表，加字段不需要迁移。** `settings` 表是 `key`-`value`，读写由
`Settings::from_pairs` / `to_pairs` 一对方法收口（写在一起，避免读写漂移），
取值范围也在那里统一夹好。所以新增外观类、开关类的设置项只改 Rust 代码，
不碰数据库；只有加表或加列才需要新的迁移文件。目前 18 个设置项都存在这张表里
（书签自定义图标是**加列**，所以走了迁移 003）。

**导入解析在服务端。** 浏览器导出的 Netscape HTML 解析（文件夹栈 → 分组、
实体解码、`<DD>` 描述）放在 `transfer.rs` 里做，纯函数、有单测。

**浏览器 HTML 的文件夹路径：首层分类进分组。** 分组取
**第一个非容器文件夹**——浏览器导出时会把所有书签套在一个容器文件夹里
（`书签栏` / `Bookmarks bar` / `其他书签` 等），那不是用户的分类，跳过它才能让
标签栏显示真正的顶层分类；用整条路径当分组名会拼出一堆长名字，用最内层则会让
「工作/项目A」和「工作/项目B」变成两个看不出共同上层的平级分组。更深层级的路径
仍然完整写进 `tags` 列（界面上不显示，但搜索会命中），所以信息没有丢。JSON 备份按
里面的分组名还原（导出写分组名，导入按名字对应，不存在就建）。

**容器文件夹既不当分组，也不进 `tags`。** 浏览器会把所有书签套在一个容器里
（书签栏 / Bookmarks bar / 其他书签…），那不是用户的分类。一开始只在分组那侧跳过了
它，`tags` 那侧仍旧照收，于是人人都多出一个「书签栏」——它不表达内容，拿它检索等于
命中全集，纯属噪音。现在两侧共用同一个 `is_container_folder` 判断。

文件读取走 `<input type="file">`，但**不把 FileReader 的回调直接接回 Rust**：
那段 JS 交给 `document::eval` 跑，读到的文本通过 `dioxus.send` 发回来，之后所有
动作都在 `onchange` 事件触发的那次 `spawn` 里做。这里踩过一个坑——原生 JS 回调
不在任何 Dioxus 作用域里，在其中写 signal 或调用 `spawn`，会让 dioxus-core 取
「当前作用域」时 `unwrap` 到 `None` 直接 panic；release 下 `panic = "abort"`，
于是整个页面死掉，现象只有控制台一句 `RuntimeError: unreachable`。
这条约束对任何 wasm 应用都成立：**原生 JS 回调里只该碰不依赖运行时状态的东西**。

**装了 panic 钩子。** 同样是 `panic = "abort"` 的后果：wasm 里 panic 只会变成一个
没有信息的 `unreachable`。钩子在 abort 之前把消息与位置打成一行 `console.error`，
并写进一个固定 id 的 DOM 节点（`#nekotab-panic`）——应用崩死之后那个节点还在，
从外部也能读到现场。上面那个坑就是靠它定位到 `runtime.rs:223` 的。

**分组图标塞进原来的 `icon` 字段，不新增表结构。** 图标值有四种形态：
`i:code`（内置图标）、`t:#rrggbb:字`（文字图标）、`http…`（图片地址）、空串（名称首字）。
内置图标是自己画的简单几何图形（`src/components/icons.rs`，24×24、线框、23 个），
不引第三方图标库：避免为几十个图标引入依赖与许可问题，而且这些形状够简单、肉眼可核对。
三个用到图标的地方（标签栏、分组管理、批量移动）走同一个渲染函数，免得样式漂移。
书签的图标（迁移 003 加的 `bookmarks.icon` 列）复用同一套取值约定，所以内置图标集、
校验函数、渲染函数都直接用现成的。

**上传壁纸走原始字节，不用 multipart。** 只需要传文件，而 multipart 要额外引
解析依赖，所以 `POST /wallpaper` 的请求体**就是图片字节**，类型由 `Content-Type`
给出，浏览器侧一个 `fetch('/wallpaper', { method: 'POST', body: file })` 就够。
文件名由服务端生成（不透明哈希 + 由 MIME 推的扩展名，原始文件名一律丢弃，
免得把用户的路径信息带进容器），删除与回发都靠**白名单式**的
`is_safe_name`（只接受「十六进制 + 已知扩展名」，挡住 `../` 与任意后缀）。
壁纸与图标是两种东西：图标是可再生缓存，有负缓存、有「清空图标缓存」；
壁纸是用户自己的数据，只由用户显式增删，不参与任何自动清理。

**请求体上限得自己放开——axum 默认只收 2 MB。** 壁纸单张上限是 16 MB，而 axum 对
`Bytes` 这类提取器的默认上限是 2 MB：超了会在**读请求体**时就被 413 掉，而且连接是
中途掐断的，浏览器只报一句 `TypeError: Failed to fetch`——我们写的那句"图片过大
（上限 16 MB）"根本没机会显示（实测：3 MB 的图直接撞这个坑，而 1 MB 以下一直没暴露
出来，因为此前测的都是小图）。两处修：`main.rs` 在 router 末尾挂一层
`DefaultBodyLimit::max(MAX_WALLPAPER_BYTES)`（`Router::layer` 作用于此前注册的全部
路由，dioxus 的 server function `/api/*` 也在内——书签导入传的是整份备份文本，
同样吃这个上限，一份 3 MB 的导出以前会以同样方式失败）；前端在选择文件时先看
`file.size`，超限的直接不发请求，当场说清是哪张、多大。

**背景池只存地址，本机文件靠地址回到目录。** 池（`settings.background_urls`，
一行一个地址）是"有哪些背景"的唯一出处，本机图在池里就是 `/wallpaper/xxx.png`
这个地址——于是轮换、缩略图、删除都只需要处理字符串，不必为"外链还是本地"
分两套数据。为什么不直接把目录列举当池：**首页渲染时只有 `Settings` 可用**（它
随首屏直出，见下文），去列目录要多一次请求、还赶不上首屏；而池随设置一起到达。
`background_url` 保留成"当前生效的那条"（池非空时必定是池里的一条），渲染路径
因此一行没改。老库里只有这一个字段，读的时候把那条当成池里的唯一一条——纯函数、
幂等、不写库，于是这个改动不需要迁移。

**「存到本地」是 server function，不是新路由。** 上传必须走原始字节路由（形状
不同），但"给我一个地址、我去取回来"的输入输出都是 JSON，正是 server function
的形状。抓取复用站点图标那套代取（`backend::http_client()`、带 UA、确认是图片
才收），两点不同：体积上限按壁纸算（16 MB）且**边读边卡**——图标是"全读进内存
再看大小"，壁纸按那个写法会被一个几百 MB 的响应打爆；失败原因（超时 / 不是图片
/ 超限 / HTTP 状态）要直接摆到界面上。

**背景池面板的 HTTP 也放在 JS 里。** 和读文件同理（见上文 Dioxus 作用域那条），
上传要拿 `<input type="file">` 的 `File` 对象、删除要拼 URL，干脆在
`document::eval` 里发请求，只把结果 `dioxus.send` 回 Rust。这样客户端不必再引
一个 fetch 库。

**设置面板是"左菜单 + 右内容"两栏。** 加进分组管理与回收站之后，单个 400px
抽屉从上滚到底太长了；现在左边选分区（外观 / 背景 / 卡片与布局 / 时钟与一言 /
打开与翻页 / 数据 / 分组管理 / 回收站），右边只看这一节，两栏各自滚动。
设置类分区共用一套"草稿 + 保存设置"，其余分区各自有即时生效的操作，所以保存条只在
设置类分区出现。

**背景那一节是例外：它改完即时落库。** 上传一张图、点一下"设为当前"、拖一下遮罩，
都是"看着调"的动作——改完还要再点一次「保存设置」才生效，用起来就是"我传了图什么
都没发生"（真发生过）。所以这一节用一个 effect 盯着草稿里背景那五项（渐变、池、
当前、遮罩、轮换开关），与"已落库的那版"不一致就去存：睡 400ms 再存（拖滑块会连发
input 事件），存完再看一眼，直到两者一致。其余设置项仍是手动保存——它们是偏好，
改完不急着落库。

**导出走普通 axum 路由而不是 server function。** `/export/bookmarks.json`、
`/export/bookmarks.html`、`/export/db.sqlite` 都注册在 `dioxus::server::router` 上，
浏览器直接以文件形式下载（带 `Content-Disposition: attachment`），客户端不需要
任何 Blob/下载相关的 wasm 胶水，也能用 curl 直接验证。数据库快照用
`VACUUM INTO` 而不是拷文件：`mtab.db` 在 WAL 模式下还有 `-wal` / `-shm` 兄弟文件，
直接拷走主文件会丢掉未 checkpoint 的写入，`VACUUM INTO` 出来的才是自洽单文件。

Netscape HTML 的导出于导入是对称的：分组写成文件夹（`<H3>` + 嵌套 `<DL>`），
未分组的放根层，属性值做实体编码。写这个导出时被自己的往返测试抓到一个老 bug：
**解析端没做实体解码**，浏览器导出时会写 `&amp;`，于是带 `&` 的 URL 会原样存进库。
现在 href 与 ICON 都会先解码再入库。

**响应压缩。** 静态产物（wasm / js / css）由 dx 在构建期压成 `.br`
（`Dioxus.toml` 的 `pre_compress`，质量 11），`dioxus-server` 的
`ServeFile::precompressed_br()` 直接把那份发出去、运行时零 CPU；`main.rs` 里
再挂一层 gzip + brotli 负责动态响应（SSR 的 HTML、server function 的 JSON）。
实测 wasm 1058 KB → gzip 423 KB → brotli 326 KB。

## 环境变量

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `DATABASE_URL` | 否 | `sqlite://data/mtab.db?mode=rwc` | SQLite 连接串 |
| `ICON_DIR` | 否 | `data/icon` | 站点图标缓存目录（字节落盘，库表只留元数据） |
| `WALLPAPER_DIR` | 否 | `data/wallpaper` | 上传的壁纸目录（用户数据，不参与缓存清理） |
| `IP` | 否 | `127.0.0.1`（Docker 中 `0.0.0.0`） | 监听地址。注意是 `IP` 不是 `HOST`——由 `dioxus-cli-config` 读取 |
| `PORT` | 否 | `8080` | 监听端口 |
| `ACCESS_PASSWORD` | 否 | 空 | 整站访问密码。留空＝不设防；设置后未登录访问跳 `/login`，登录状态保持 **30 天** |
| `SESSION_SECRET` | 否 | 用密码派生 | 会话签名密钥。想轮换密码又不让所有设备退出时固定它；改了它＝全部会话失效 |

复制 `.env.example` 为 `.env` 后按需修改。

**访问密码。** 设置 `ACCESS_PASSWORD` 后：
- 页面、server function（`/api/*`）、导出、图标与壁纸都受保护；登录页、静态产物与
  带令牌的 `/api/bookmark` 放行（书签小工具从别的站点发起请求，没有本站 Cookie）。
- Cookie 是 `HttpOnly; SameSite=Lax`，HTTPS 下自动加 `Secure`（需要反代传
  `X-Forwarded-Proto: https`）；服务端不存会话表，签名里带过期时间，重启后仍有效。
  没设 `SESSION_SECRET` 时，服务端会生成一个随机密钥存进 `settings.session_secret`，
  再用它和密码派生签名密钥——只拿到 Cookie 的人无法离线快速枚举密码。
- 连续输错 8 次后，**错误的尝试**会被挡 60 秒（正确密码仍可进，避免匿名者把站长锁在门外）；
  公网部署仍建议在反向代理层再加 HTTPS 与限流。
- 纯 HTTP 下密码是明文传输的——内网也要清楚这一点，公网请务必上 HTTPS。

**为什么还有几处叫 `mtab`。** 应用名统一成了 NekoTab，但**数据所在位置**的名字有意
没跟着改：数据库文件仍是 `mtab.db`，`docker run` 示例里的卷名仍是 `mtab-data`。
改个名字容易，改数据位置会让人看着像"书签全没了"——沿用旧名字，现有部署升级后
照样读到原来的库。要把这些一并改成 `nekotab.*`，那是一次数据迁移（移动文件 +
改环境变量），不是重命名，得单独做。

## 生产构建

```bash
dx build --release --platform web
```

产物在 `target/dx/nekotab/release/web/`：客户端资源在 `public/`，
服务端二进制名为 `server`（Windows 下 `server.exe`）。

**务必用 release 构建对外提供服务。** 开发构建的 wasm 有 63 MB（不优化且带调试
信息），正式构建约 1.4 MB，brotli 后约 400 KB。

> Windows 上**先把正在运行的服务停掉再构建**：服务端二进制与 `public/` 里的产物
> 会被占用，`dx build` 写不进去，报的错是「另一个程序正在使用此文件」，
> 或 wasm-opt 阶段的「系统找不到指定的路径」——看着像路径问题，其实是文件锁。

## Docker

### 用已发布的多架构镜像（推荐）

`docker-compose.yml` 默认直接拉 `remloyal001/nekotab:latest`（amd64 + arm64 合在一个
manifest 里）：

```bash
docker compose up -d                        # 拉取并启动
docker compose pull && docker compose up -d  # 升级到新镜像
docker compose logs -f
```

数据用 bind mount 放在宿主目录，默认是仓库下的 `./data`（与本地开发的约定一致），
可用 `NEKOTAB_DATA` 指向别处、`NEKOTAB_PORT` 换宿主端口。
**要放在本地磁盘，别放 NFS / SMB 这类网络文件系统**——SQLite 的 WAL 依赖正常文件锁。

### 自己构建

```bash
docker build -t nekotab .
# 需要整站访问密码时，在下面的命令里加：
#   -e ACCESS_PASSWORD='换成你的密码' -e SESSION_SECRET='一串随机字符' \
docker run -d --name nekotab \
  -p 8080:8080 \
  -v mtab-data:/data \
  nekotab
```

镜像是多阶段的：构建阶段装工具链并跑一次 `dx build --release --platform web`，
运行阶段只留 `debian:bookworm-slim` + 产物。首次构建要下 Rust 镜像、`cargo install
dioxus-cli` 并全量编译，是十几分钟量级；之后由 Docker 层缓存接管。

**构建不需要访问 GitHub。** dx 收尾会想从 GitHub Releases 下 wasm-opt（binaryen），
在连不上 GitHub 的网络里整个构建会倒在最后一步、且报错像"编译失败"。所以
`Dockerfile` 里把发行版的 `binaryen` 直接放进 dx 的工具缓存目录，让它不去下载
（细节写在 Dockerfile 的注释里，含"dx 升级后要跟着改哪个数字"）。

要「本地编译一次、部署时秒构建」，用 `Dockerfile.prebuilt`：先在 **Linux 环境**
（WSL / CI / rust 容器）里跑 `bash scripts/pack-linux.sh` 把产物打到 `dist/<arch>/`，
再以那个目录为上下文构建运行镜像。产物**必须是 Linux 的**——Windows 上 dx 产出的是
`server-*.exe`，容器里跑不起来。

`scripts/publish.sh` 把上面两步连起来：本机按架构打包 → 各架构分别 build & push →
合成多架构 manifest。Git Bash / MSYS 下它会自动把自己丢进 WSL 重跑一遍，所以
**Windows 上直接 `bash scripts/publish.sh` 即可**。支持 `DRY_RUN=1`（只打印命令）、
`SKIP_BUILD=1`、`ARCHES=...`。

### 数据、升级与出网

数据落在 `/data/mtab.db`（连同 WAL 的 `-wal` / `-shm` 文件），图标落在 `/data/icon`，
上传的壁纸落在 `/data/wallpaper`：容器重建都不丢。镜像里 `ICON_DIR` 与
`WALLPAPER_DIR` 都已指向挂载卷。

**升级只需换镜像**：数据库迁移随二进制编译进去（`sqlx::migrate!`），启动时自动应用，
没有单独的迁移步骤。

但要留意**反向不成立**：拿旧镜像跑已经升级过的库会**直接启动失败**，报
`migration N was previously applied but is missing in the resolved migrations`
——sqlx 默认不允许"库里已应用、而当前二进制里没有"的迁移。回退镜像时得先把多出来的
那几条记录从 `_sqlx_migrations` 里删掉（列本身可以留着，旧代码不认识就不会碰）。

**007 是个例外。** 它给 `bookmarks` 加了 `group_ids` 列；只删迁移记录、留着列的话，
之后再升级回带 007 的版本会因 `ALTER TABLE ... ADD COLUMN group_ids` 报
`duplicate column name` 而启动失败。要回退到 007 之前再升回来，先执行
`ALTER TABLE bookmarks DROP COLUMN group_ids;`（SQLite ≥ 3.35）或直接用升级前的备份。
旧镜像运行时只会写 `group_id`；新版本读取时会把主分组补进 `group_ids` 的归属里，
所以降级期间改过的分组不会在新版本里凭空消失（但可能同时出现在旧分组和目标分组下，
彻底对齐需要重新编辑一次该卡片）。

**「一言」与「天气」需要服务端能出网**（前者取一言接口，后者取 Open-Meteo，
都不需要密钥）。纯内网部署时这两处会保持空白 / 显示取不到，其余功能不受影响。

注意：服务端运行时会读取可执行文件同级的 `public/` 目录，因此镜像里要连同
`public/` 一起拷贝，不能只拷二进制。

## CI/CD 与发布

仓库自带两条 GitHub Actions 工作流，都在 `.github/workflows/` 下。

### 持续集成（`ci.yml`）

push 到 `main` 和 PR 时触发（也可手动 `workflow_dispatch`）：

- 服务端 `cargo check`
- 客户端 `cargo check --target wasm32-unknown-unknown`
- `cargo test`（服务端单测）

工具链固定 1.94，与 `Dockerfile` 的 `rust:1.94` 对齐；依赖里最高的 MSRV 是 1.89。
这里只做 check、不跑完整 `dx build`，把十几分钟的产物构建留给发布流程。
`cargo fmt --check` 暂未纳入：现有代码没有按当前 rustfmt 格式化，直接加会让 CI 一上来
就红；要强制的话先单独跑一遍 `cargo fmt`。

### 发布（`release.yml`）

**推一个 `v*` 标签就会发布**，版本号必须与 `Cargo.toml` 的 `version` 一致，
否则工作流会在校验版本那一步直接失败：

```bash
# 先把 Cargo.toml 的 version 改成 0.2.0 并提交
git tag -a v0.2.0 -m "NekoTab 0.2.0"
git push origin v0.2.0
```

发布流程做的事：

1. 用 `scripts/pack-linux.sh` 构建 **amd64 + arm64** 的 Linux 产物：客户端 wasm 只编
   一次，服务端在 amd64 上原生编、在 arm64 上交叉编（装 `gcc-aarch64-linux-gnu`），
   不走 QEMU 模拟编译。
2. 用 `Dockerfile.prebuilt` 打成多架构镜像并推送：
   - `ghcr.io/remloyal/nekotab`（用 `GITHUB_TOKEN`，无需额外配置）
   - `remloyal001/nekotab`（**可选**，见下方 secrets）
3. 推镜像前先用 amd64 镜像起一次容器、等首页返回 200，避免把坏镜像推成 `latest`。
4. 创建 GitHub Release，附两个架构的 `nekotab-<版本>-linux-{amd64,arm64}.tar.gz`
   和 `SHA256SUMS`。解压后 `server` 与 `public/` 同级，设置环境变量即可直接运行。

镜像标签规则：`<版本>`（如 `0.2.0`）；非预发布同时更新 `latest`。
标签里带 `-` 的（如 `v0.2.0-rc1`）按预发布处理：不碰 `latest`，Release 标为
pre-release。

**可选的 Docker Hub 推送。** 不配置就只发 GHCR。要用 Docker Hub，在仓库
Settings → Secrets and variables → Actions 里加：

| Secret | 内容 |
| --- | --- |
| `DOCKERHUB_USERNAME` | Docker Hub 用户名（填 `remloyal001` 才能与 `docker-compose.yml` 的默认镜像一致） |
| `DOCKERHUB_TOKEN` | Docker Hub 的 Access Token（不是登录密码） |

**GHCR 的包默认是私有的。** 想让别人直接 `docker pull`，到 GitHub 个人/组织设置的
Packages 里把 `nekotab` 的可见性改成 public。

## 已知限制

- **鉴权是可选的。** 不设置 `ACCESS_PASSWORD` 时整站不设防（单用户自部署的默认），
  公网暴露请设置它，或在反向代理上加鉴权。`/api/bookmark` 另有自己的令牌把关
  （见「快捷添加」）；反代若只做 Basic Auth，记得那条路径同样要覆盖到。
- **一条书签可以属于多个分组**，因此会出现在多个分类标签页下；「全部」的条数按书签数算，
  不会因为多分组而重复。标签功能仍不在界面上（见「标签从此退出界面」），数据库里的
  `tags` 列和已有的值都还在。Netscape 导出只能写一个分组（取主分组），多分组完整还原
  请用 JSON 备份。
- **没有做「文件夹卡片」**（把一组链接折叠成一张卡片）。分组已经承担了归类职责，
  再叠一层文件夹会让「分类标签页 + 卡片网格」两套导航互相打岔。
- **搜索联想只认已知引擎。** 联想接口是各家的私有端点、格式互不相同，所以只有一张
  写死的表：百度 / 必应 / 谷歌 / 360 / 搜狗。自己加的引擎（比如自建 SearXNG）没有
  联想词，面板就不出现。服务端拿不到响应时同样静默为空，搜索本身照常用。
  另外，联想是把**你正在输入的词**发给对应搜索引擎换回来的——介意这一点就不要用
  它（输入完直接回车照样搜）。
- **滚轮翻页默认关闭**：开启后滚轮会被拦下来翻页、不再滚动页面。
- **跨格卡片会留洞，且 Netscape 导出丢跨度。** 网格用默认的稀疏排布（不做 dense
  回填），因为回填会让视觉顺序与数据顺序分家，拖拽落位和分页立刻变得不可预期；
  代价是同一行放不下的大卡片会被挤到下一行，中间留洞。另外跨度只有 JSON
  备份能原样搬回，`/export/bookmarks.html`（Netscape 格式）没有这个概念，
  导回浏览器再导回来一律变成 1×1。
- **书签卡做成纵向长条时上下会留白。** 图标块按格子的**短边**缩放（这样跨格时不会
  中间一个小图标、四周一圈空），所以 1×3 / 2×3 这种"窄而高"的书签卡，图标仍受宽度
  约束，纵向空间就空着。组件卡会把它用满——记事本、天气、两个时钟都按格子的宽高
  自适应排版。
- **拖拽排序作用在全量顺序上。** 筛选或分页时，被拖的卡片落到**目标在全量里的
  位置**，中间那些书签（包括被筛掉、当前看不见的）依次让位。所以看到的落位与
  最终顺序一致；代价是一次跨页拖动会连带挪动中间的书签——这是「顺序唯一」的必然
  结果，不做「只重排可见项」那种会让人下次打开时莫名其妙的分裂语义。
- **触屏拖拽要先进入编辑态**（长按卡片）：编辑态下卡片带 `touch-action: none`，
  从卡片上起手不会滚动页面——这是让拖拽可用的代价。
- **一言需要服务端能出网。** 拉取失败时该行保持空白（不影响其他功能）。
  换一条的间隔改 `src/components/quote.rs` 的 `REFRESH_SECS`。
- **背景图有两种来源**：填任意图片直链（由浏览器直接加载，需要对方允许跨站引用——
  CSS 背景图不受 CORS 限制，但可能被防盗链拦），或者**上传到服务器 / 用「存到本地」
  抓回服务器**（见上，都不受防盗链影响）。轮换或随机图模式下每次打开都会真下载
  一张图（实测约 1MB / 2 秒），且要在 hydration 之后才开始，首屏会有一小段没有
  壁纸——这也是内置壁纸预设存在的理由。
- **「存到本地」是一次显式动作，不做自动。** 外链图只在用户点「存本地」时才抓回
  自己服务器（否则会静默把磁盘堆满）；抓回来之后池里那条就是本机地址，与其他
  本机图一样可删、可移出池。
- **本机壁纸不参与任何自动清理。** 池里移出只是不再参与轮换，文件仍在
  `WALLPAPER_DIR`；要真的释放磁盘得点「删除」（不可恢复）。所以"本机文件"条带
  会一直列出不在池里的那些，避免它们变成看不见的占用。
- **农历只覆盖 1900–2100 年**，超出范围不显示。
- **图标是缓存，不是数据，取不到会回退首字色块。** `/icon/{host}` 返回 404
  表示"这个站点没有可取到的图标"，不是故障：卡片会露出名称首字 + 哈希取色的色块。
  实际上确实有不少站点取不到——`/favicon.ico` 返回 HTML 且 head 里也不声明图标
  （实测 `pre.friggatech.com` 这类就是），或者站点从服务器所在网络不可达。
  内网/本机地址（`172.16.x.x`、`localhost:8000`）在容器里通常也取不到，
  除非容器确实能访问那些服务。取不到的原因会打进服务端日志，也可以在设置里
  「清空图标缓存」强制全部重新代取。低分辨率图标（16×16）在大尺寸卡片上会偏软，
  这是源文件本身的限制。
- **迁移是「基线 + 追加」**：`001_init.sql` 是合并后的单一基线，
  它**一旦被部署过就不能再改**——sqlx 会校验已应用迁移的校验和，改动会导致
  启动直接失败（`migration N was previously applied but has been modified`）。
  这条踩过两次。今后任何表结构变更都必须**新增**文件。
  迁移 002 把 `favicons` 表整个重建（字节改落盘），旧的图标缓存会丢失并在
  下次访问时重取——它是纯缓存，这是有意的取舍。
  迁移 005 给 `bookmarks` 加了 `kind` / `config` 两列来承载**组件**（见下），
  默认值都是空串，所以对既有数据是零行为变化。
- **组件与书签共用一张表、一套顺序**（`bookmarks.kind`：空串是书签，`clock` 是
  数字时钟）。好处是拖拽、跨度、编辑态、`data-bookmark-id` 落点这些都不用为组件
  重写一遍；代价是凡"只该管书签"的地方都要按 `kind` 收口，现在有四处：列表查询带
  上两样再由前端分流、导出排除组件、URL 去重与查重加上 `kind = ''`、`clean_bookmark`
  按 kind 走两条校验。加新组件只动 `models::WIDGET_KINDS` 与渲染分支。
- **组件不进书签导出。** `/export/bookmarks.json` 与 `/export/bookmarks.html` 都只
  导书签：组件的网址是空的，写进给浏览器导入的书签文件只会留一条打不开的链接。
  要连带组件一起备份，用 `/export/db.sqlite`（整库快照）。
- **组件不参与筛选、分组计数与分页**，且固定显示在书签之前。它不是"多、要筛、要翻页"
  的东西；被关键词筛掉或被翻到第二页都只会让版面突然缺一块。拖拽也只在同类之间
  生效——跨类落位没有可解释的结果，会直接忽略。
- **组件的参数存在 `config` 这个 JSON 串里**，服务端按 kind 规范化后才落库（多余字段
  丢掉、缺的按默认补上），客户端解析失败一律回落默认值。所以脏数据只会让某张卡片
  显示成默认样式，不会让整页渲染不出来。
- **记事本的正文是"弹窗里改"，不是"卡片上直接敲"。** 在卡片上放可输入的文本域要和三条
  既有行为抢指针——长按进编辑态、从卡片任意处起手拖拽、编辑态下的 `touch-action: none`
  ——再叠一层防抖自动保存，以及"父级刷新把没保存的本地文本冲掉"的保护。那是独立的一件事，
  没混进这一版。卡面因此是只读的，点一下打开编辑器（一次点击，不需要右键找菜单）。
- **天气需要服务端能出网**，数据源是 [Open-Meteo](https://open-meteo.com)（选它的唯一理由
  是**不需要 API key**：要注册账号、要配密钥的数据源会把"部署完就能看天气"变成"先去申请
  一个密钥"）。地图名先在服务端换成经纬度再取预报，两次请求都走同一个 8 秒超时的客户端。
  取不到时**卡片上直接写明原因**（"找不到「xx」这个地方"／连接失败的原话），而不是留一片
  空白——这与「一言」的取舍相反，一言取不到就保持空白无所谓，天气卡片空着只会被当成坏了。
  已经取到过数据时，后续刷新失败会保留旧值。
  客户端每 **10 分钟**刷新一次，服务端**不做缓存**：一个开着的页面一小时四次请求，
  自己用足够了；要多开几个标签页的话，考虑给它加一层缓存。换数据源只需改
  `src/weather.rs` 里的两个地址与两个解析函数。
- **服务端搜索接口目前前端不再调用**（筛选搬到客户端了），能力与单测都还在。
- **热搜依赖服务端出网。** 五个源都是各家公开接口，可能改格式、限流或需要特定 UA；
  取不到时卡片上会写明原因，换一个源即可。服务端按源缓存十分钟，客户端每十分钟刷新。
- `created_at` 存 UTC 时间字符串，界面未展示；回收站里的删除时间按 UTC 显示。
