# mtab-lite

极简、可自部署的书签导航页，界面参照浏览器新标签页：大字时钟（带农历）+
搜索引擎框 + 分类标签页 + 图标网格。

用 [Dioxus 0.7](https://dioxuslabs.com/) fullstack 写成：同一份 Rust 代码编译出
服务端（Axum + SSR）和浏览器端（WASM + Hydration），数据存单文件 SQLite。

## 功能

**首页**

- **时钟**：实时时钟 + 日期，可另开农历（如「二〇二六年九月初四」）与
  「第 N 天 · 第 N 周」，都可在设置里关掉。
- **一言**：时钟下方一句「一言」，默认每 5 分钟换一条。服务端代取接口，
  失败时保留上一条，不显示错误、不打断页面。
- **搜索框（两种用途）**：右侧按钮在「网页 / 书签」之间切换。
  - **网页**：左侧选搜索引擎，回车或点 `→` **在新标签页**搜索，当前书签页不受影响。
  - **书签**：输入即筛下方卡片（同时匹配名称、网址、描述、标签），回车不跳转。
- **引擎前缀**：给某个引擎配了前缀后，输入「前缀 + 空格 + 关键词」即可临时改用它，
  例如给 GitHub 配 `gh`，输入 `gh rust` 就用 GitHub 搜 rust。前缀必须独立成段，
  所以输入 `github` 不会被误当成前缀 `gh`。
- **分类标签页**：由**分组**驱动（`全部 12` / `未分组 3` / `开发 5`），点选即筛选；
  没有书签的分组自动从标签栏消失。标签页条数跟随当前结果集变化。
- **添加书签**：页面**空白处右键 → 添加卡片 → 网址导航**，或点网格末尾的＋。
- **打开**：点图标打开对应网址；开新标签页还是当前页由设置决定。
- **站点图标**：卡片上自动显示对应站点的真实图标（服务端代取并缓存到磁盘）；
  取不到时回退成「名称首字 + 哈希取色」的彩色块。

**整理书签**

- **卡片编辑态**：**长按卡片**（按住约 0.5 秒）进入编辑态——卡片显示 ✕ 删除角标与
  拖拽手柄，底部出现操作栏。此时：
  - **拖动**卡片调整顺序（鼠标与触屏都支持，落位后写回数据库）；
  - **点卡片**打开修改弹窗（名称 / 网址 / 描述 / 分组 / 标签，字段预填）；
  - **点 ✕** 二次确认后删除（进回收站，可还原）。
- **批量操作**：编辑态点「批量选择」进入选择模式——点卡片切换选中，
  底栏可**打标签**、**移到分组**、**批量删除**（都进回收站），另有「全选本页」。
- **右键菜单**：卡片上可打开 / 编辑 / **移到分组** / 批量选择（从这条开始）/ 删除；
  空白处可添加卡片 / 刷新列表。
- **回收站**：删除是软删除，书签先落在设置里的回收站，可逐条还原或彻底删除、
  也可以一次清空。
- **分组管理**：设置里增删改分组、配图标、用 ↑ ↓ 调整标签页顺序。
  删除分组不会删书签，组内书签归到「未分组」。
- **分页**：书签多了可以在设置里设「每页卡片数」，用圆点、翻页按钮、
  `←` `→`、`PageUp` `PageDown`、鼠标滚轮（可选）或触屏左右滑动翻页，
  还能开循环翻页。

**外观**

- **主题**：深色 / 浅色两套，配色走 CSS 变量。
- **内置壁纸**：6 套纯 CSS 渐变（极光 / 星云 / 森林 / 海洋 / 晚霞 / 素墨），
  深色浅色各一套配色；也可以填任意图片直链，支持亮度遮罩与「每次打开换一张」。
- **卡片与布局**：卡片宽度、横向 / 纵向间距、每行列数（0 为自适应）都可调，
  设置里带实时预览。
- **简约模式**：只留壁纸、时钟和搜索框，把网格整个隐藏。

**数据**

- **导入**：设置里可直接**选文件**（浏览器导出的书签 HTML 或本应用 JSON 备份），
  也可以把内容粘贴进文本框。按 URL 自动去重；JSON 备份里的分组会一并还原
  （分组不存在则自动创建）。
- **导出**：一键下载无损 JSON 备份（含标签、分组与顺序），能原样搬回来。

**键盘**

- `Ctrl/Cmd + K`：焦点回到搜索框
- `Esc`：按层级依次关闭右键菜单 → 弹窗 → 设置抽屉 → 批量选择 / 编辑态
- `←` `→` `PageUp` `PageDown`：翻页（焦点在有内容的输入框里时让路给光标）

## 技术栈

| 层 | 选型 |
|----|------|
| 全栈框架 | Dioxus 0.7.10（`fullstack` + `router`） |
| 服务端 | Axum 0.8（由 `dioxus::serve` 托管） |
| 数据库 | SQLite + sqlx 0.9（异步连接池，WAL） |
| 序列化 | serde / serde_json |
| 配置 | dotenvy |
| 一言（仅 server） | reqwest（复用 dioxus 已有的 rustls，无系统 OpenSSL 依赖） |
| 响应压缩（仅 server） | tower-http（gzip + brotli） |
| 时钟 / 农历 / 搜索跳转 / 指针拖拽 / 文件读取（仅 web） | js-sys、gloo-timers、web-sys、wasm-bindgen |

**没有第三方日期库。** 农历是「一张 1900–2100 年的编码表 + 几十行算术」，
自己写在 `src/lunar.rs` 里，配套单测拿历年春节（正月初一）的公历日期校验——
表里任何一格抄错都会让某一年的正月初一对不上，所以这组测试是有效护栏。

## 关键设计

**Feature 隔离。** 依赖按编译目标切开，`sqlx` / `tokio` / `dotenvy` / `reqwest` /
`tower-http` 只在 `server` 下启用，`js-sys` / `gloo-timers` / `web-sys` /
`wasm-bindgen` 只在 `web` 下启用：

```toml
[features]
default = []
web    = ["dioxus/web", "dep:gloo-timers", "dep:js-sys", "dep:wasm-bindgen", "dep:web-sys"]
server = ["dioxus/server", "dep:sqlx", "dep:tokio", "dep:dotenvy", "dep:anyhow", "dep:reqwest", "dep:tower-http"]
```

WASM 产物里不含数据库驱动与 HTTP 客户端；服务端二进制里不含浏览器 JS 绑定。

**连接池初始化。** 建池是异步的，而 `OnceLock::get_or_init` 只接受同步闭包，
所以在 `main` 里先 `await db::init_pool(...)`，再 `set` 进 `OnceLock`。建池时
开 `create_if_missing`、`journal_mode = WAL`，并执行 `sqlx::migrate!` 跑迁移；
同时会补建数据库文件与图标目录的父目录。

**分组取代了「标签即分类」。** 早期版本的分类标签页由书签的 `tags` 去重派生，
代价是无法给分类排序、配图标，且一条书签带多个标签就会在多个标签页里重复出现。
现在分类是显式的 `groups` 表：一条书签归属至多一个分组（`NULL` 即「未分组」，
不占一行、由前端合成），而标签保留下来只作检索词——服务端搜索与客户端筛选
都会匹配它。

分组的删除是「归位」而非级联：`delete_group` 在同一个事务里把组内书签的
`group_id` 清空，书签本身不动。读列表时前端还会把「指向已不存在的分组」当作
未分组处理，兜住并发删除这类边角——否则那条书签在任何标签下都看不见。

**列表恒为全量，筛选与分页都在客户端。** 书签列表始终取全部
（`list_bookmarks("")`），分类筛选、关键词筛选、分页都只影响**显示**。
这样拖拽重排永远作用在完整顺序上。服务端那套按关键词的 AND/OR 模糊搜索仍然
保留（`POST /api/list_bookmarks` 传 `{"query":"..."}` 即可用），客户端为
「输入即筛」把它搬到了本地，两边口径一致。

**拖拽排序：把视图内的新顺序合并回全量顺序。** 分页和筛选让「看见的」变成全量的
一个子集，直接按视图下标写 `sort_order` 就会把别的书签挤乱。所以落位时用
`merge_order`：视图覆盖到的那些位置按新顺序重填，其余位置原样不动，写回服务端的
始终是**完整顺序**。这个函数还会先校验「新顺序确实是视图中那批 id 的一个排列」，
不满足就整个放弃——排序是低频操作，多一次比较换来「任何输入都不会把顺序弄乱」。

**拖拽走 Pointer Events，鼠标与触屏同一条路径。** 原生 HTML5 拖放在触屏上不触发，
而且 `<a>` 的默认拖拽会把链接地址当拖拽数据，两者会打架。所以按下时尽力把指针
捕获到卡片上（拖出网格也能继续跟踪），**判定与落点计算则放在网格这一层**——
网格是所有卡片的公共祖先，指针捕获失败时移动事件仍会从下方的元素冒泡上来，
拖拽不会因此失效。落点用 `document.elementFromPoint` 做命中测试，
比逐个读卡片矩形便宜。位移超过 8px 才算拖动，抬手后那一次 `click` 会被吞掉，
不会顺手弹出修改弹窗。

**长按与拖拽共用按下事件。** 普通态按下 500ms 且期间位移不超过 8px 才进入编辑态；
编辑态按下则直接进入待拖拽状态。触屏上编辑态的卡片带 `touch-action: none`，
否则拖拽会被浏览器当成滚动手势。

**删除是软删除。** `deleted_at` 置时间戳，列表查询一直带
`deleted_at IS NULL`，所以回收站里见到的是「删了但还在库里」的那些；
只有「彻底删除」才真的 `DELETE`。误删的代价从「不可恢复」变成「点两下还原」。

**站点图标落盘，库里只留元数据。** 图标字节写在 `ICON_DIR`
（默认 `data/icon`）下的独立文件里，`favicons` 表只存
`content_type` / `file_name` / `fetched_at`。这是有意的：几十 KB 一张的图标
塞进 SQLite 会让 `mtab.db` 迅速膨胀，备份、WAL 和 `VACUUM` 都跟着变重，
而图标本来就是可重取的缓存。写盘用「先写 `.tmp` 再改名」，避免半个文件被当成
图标读走并缓存 7 天。

取图顺序：先试站点自带 `/favicon.ico`，不是图片再抓首页 HTML 解析
`<link rel="icon">`（`apple-touch-icon` 优先，一般分辨率更高）。两步都必须校验
`Content-Type` 是 `image/`——实测 `claude.ai` 对任意路径都返回 `200 + text/html`，
不校验就会把整个网页当成图标存下来。这个接口**只服务本站已收藏的站点**：
要探测就得先加书签，顺带把这个无鉴权接口被当成任意出站探测（SSRF）入口的风险
压掉了。取不到会写一条空数据的负缓存，7 天内不再重试。

**搜索提交必须走 JS，不能用原生表单。** 最初的做法是
`<form method="GET" action="{引擎地址，%s 已替换}">`，指望浏览器直接导航过去。
**这是错的**：按 HTML 规范，表单 GET 提交会**替换** action URL 里原有的查询串，
于是搜索词被清空，实测拿到的是 `https://www.baidu.com/s?`（查询词没了）。
而且各引擎参数名不同（百度 `wd`、谷歌 `q`、必应 `q`），还有把词放在路径里的
模板，原生表单无法通用地表达。所以改为拦掉原生提交、由 JS 精确打开那个 URL。
`window.open` 由用户手势（点击 / 回车）触发，不会被弹窗拦截；表单上仍保留
`action` / `target` 作为「JS 没跑起来」时的静态兜底。

**引擎存在数据库里。** `engines` 表带 `active` 标记与 `prefix` 前缀。
前缀在服务端会被规范化为「小写 + 只留字母数字与连字符」，并拒绝与其他引擎重复；
前端只在「前缀独立成段且后面还有关键词」时才认它，避免把 `github` 拆成 `gh` + `ithub`。

**一言由服务端代取。** 浏览器不直接访问 `v1.hitokoto.cn`，而是调用自己的
`get_quote` server function，由服务端发请求。这样避开跨域、统一做 8 秒超时；
失败时前端保留上一条。`reqwest::Client` 用 `OnceLock` 复用，避免每次请求重做
TLS 握手。

**时钟与农历的 SSR 一致性。** SSR 阶段无从得知「现在」，因此时钟首屏渲染空串，
挂载后由 `use_future` 每秒刷新。服务端与客户端首次渲染结果一致，不会 hydration
失配。农历、第几天、第几周都是纯计算，跟着每秒刷新一起算，不发任何请求。

**主题与背景分成两层。** 主题只换 CSS 变量（`[data-theme="light"]` 里重定义
一批变量），组件规则一行都不用改。背景分两个绝对定位层：底衬层（默认渐变或
内置预设，由 CSS 类决定）与壁纸层（内联 `background-image`）。这么分是因为
dioxus 的解释器在把 `style` 设成空串时，会把「之前设过、现在没了」的内联属性
**补回来**——于是「清空背景图」要刷新才生效；壁纸层改成始终显式写
`background-image: none` 或 `url(...)`，属性一直有值，就没有可补的东西。
两层分开则让「内联图片」和「CSS 渐变」不会互相覆盖。

**快捷键要挂在可聚焦的节点上，首屏还得主动送焦点进去。** 键盘事件靠焦点冒泡，
所以根节点带 `tabindex="0"`。但页面加载完成后 `document.activeElement` 是
`<body>`，而 body 不在根节点子树里——挂在根上的 `Esc` / `Ctrl+K` / 翻页键
一个都收不到。所以挂载后主动把焦点送进搜索框（只在焦点确实无处可去时）。
另外「方向键翻页」只在焦点位于**有内容的**输入框时才让路：搜索框默认聚焦，
若只按标签名判断，翻页键就永远用不上，而空输入框里本来也没有光标可移。

**设置是键值表，加字段不需要迁移。** `settings` 表是 `key`-`value`，读写由
`Settings::from_pairs` / `to_pairs` 一对方法收口（写在一起，避免读写漂移），
取值范围也在那里统一夹好。所以新增外观类、开关类的设置项只改 Rust 代码，
不碰数据库；只有加表或加列才需要新的迁移文件。目前 18 个设置项都存在这张表里。

**导入解析在服务端。** 浏览器导出的 Netscape HTML 解析（文件夹栈 → 标签、
实体解码、`<DD>` 描述）放在 `transfer.rs` 里做，纯函数、有单测。
**浏览器 HTML 的文件夹路径只进标签**：嵌套路径没有唯一的分组归属，硬套成
「分组」会随浏览器与层级不同产生一堆碎分组；分组只在自家 JSON 备份里往返
（导出写分组名，导入按名字对应，不存在就建）。文件读取走 `<input type="file">`
加 `FileReader`（`src/dom.rs`），拿到的文本与粘贴走同一条提交路径。

**导出走普通 axum 路由而不是 server function。** `/export/bookmarks.json`
注册在 `dioxus::server::router` 上，浏览器直接以文件形式下载（带
`Content-Disposition: attachment`），客户端不需要任何 Blob/下载相关的 wasm 胶水，
也能用 curl 直接验证。

**响应压缩。** 静态产物（wasm / js / css）由 dx 在构建期压成 `.br`
（`Dioxus.toml` 的 `pre_compress`，质量 11），`dioxus-server` 的
`ServeFile::precompressed_br()` 直接把那份发出去、运行时零 CPU；`main.rs` 里
再挂一层 gzip + brotli 负责动态响应（SSR 的 HTML、server function 的 JSON）。
实测 wasm 1058 KB → gzip 423 KB → brotli 326 KB。

## 环境变量

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `DATABASE_URL` | 否 | `sqlite://data/mtab.db?mode=rwc` | SQLite 连接串 |
| `ICON_DIR` | 否 | `data/icon` | 站点图标缓存目录（字节落盘，库表只留元数据） |
| `IP` | 否 | `127.0.0.1`（Docker 中 `0.0.0.0`） | 监听地址。注意是 `IP` 不是 `HOST`——由 `dioxus-cli-config` 读取 |
| `PORT` | 否 | `8080` | 监听端口 |

复制 `.env.example` 为 `.env` 后按需修改。

## 本地开发

先装与依赖版本一致的 CLI：

```bash
cargo install dioxus-cli --version 0.7.10 --locked
```

然后：

```bash
cp .env.example .env
dx serve            # 开发模式，默认 http://127.0.0.1:8080
```

## 生产构建

```bash
dx build --release --platform web
```

产物在 `target/dx/mtab-lite/release/web/`：客户端资源在 `public/`，
服务端二进制名为 `server`（Windows 下 `server.exe`）。

**务必用 release 构建对外提供服务。** 开发构建的 wasm 有 63 MB（不优化且带调试
信息），正式构建约 1.4 MB，brotli 后约 400 KB。

> Windows 上**先把正在运行的服务停掉再构建**：服务端二进制与 `public/` 里的产物
> 会被占用，`dx build` 写不进去，报的错是「另一个程序正在使用此文件」，
> 或 wasm-opt 阶段的「系统找不到指定的路径」——看着像路径问题，其实是文件锁。

## Docker

```bash
docker build -t mtab-lite .
docker run -d --name mtab-lite \
  -p 8080:8080 \
  -v mtab-data:/data \
  mtab-lite
```

数据落在 `/data/mtab.db`（连同 WAL 的 `-wal` / `-shm` 文件），图标落在
`/data/icon`，容器重建都不丢。镜像里 `ICON_DIR` 已指向挂载卷。

注意：服务端运行时会读取可执行文件同级的 `public/` 目录，因此镜像里要连同
`public/` 一起拷贝，不能只拷二进制。

## 已知限制

- **无鉴权。** 单用户自部署定位，公网暴露请自行加反向代理鉴权。
- **一条书签只属于一个分组**（标签可以多个）。若需要「同一书签出现在多个分类下」，
  那是早期「标签即分类」的行为，已刻意改掉。
- **没有做「文件夹卡片」**（把一组链接折叠成一张卡片）。分组已经承担了归类职责，
  再叠一层文件夹会让「分类标签页 + 卡片网格」两套导航互相打岔。
- **没有搜索联想 / 搜索建议**：那要依赖第三方接口，和「一言需要出网」是同一类
  问题，纯内网部署会失效，所以不做。
- **滚轮翻页默认关闭**：开启后滚轮会被拦下来翻页、不再滚动页面。
- **拖拽排序作用在全量顺序上。** 筛选或分页时，拖动只影响当前视图覆盖到的那些
  位置（其余书签相对顺序不变），所以看到的落位与最终顺序一致，但不会把
  被筛掉的书签一起挪动。
- **触屏拖拽要先进入编辑态**（长按卡片）：编辑态下卡片带 `touch-action: none`，
  从卡片上起手不会滚动页面——这是让拖拽可用的代价。
- **一言需要服务端能出网。** 纯内网部署时拉取会失败，此时该行保持空白
  （不影响其他功能）。换一条的间隔改 `src/components/quote.rs` 的 `REFRESH_SECS`。
- **背景图只能是图片直链**，没有上传功能；填的地址会由浏览器直接加载，
  因此需要对方允许跨站引用（CSS 背景图不受 CORS 限制，但可能被防盗链拦）。
  随机图模式下每次打开都会真下载一张图（实测约 1MB / 2 秒），且要在 hydration
  之后才开始，首屏会有一小段没有壁纸——这也是内置壁纸预设存在的理由。
- **农历只覆盖 1900–2100 年**，超出范围不显示。
- **图标是缓存，不是数据。** 手工清掉 `ICON_DIR` 后会被按需重取；
  取不到时前端回退首字色块。低分辨率图标（16×16）在大尺寸卡片上会偏软，
  这是源文件本身的限制。
- **迁移是「基线 + 追加」**：`001_init.sql` 是合并后的单一基线，
  它**一旦被部署过就不能再改**——sqlx 会校验已应用迁移的校验和，改动会导致
  启动直接失败（`migration N was previously applied but has been modified`）。
  这条踩过两次。今后任何表结构变更都必须**新增**文件。
  迁移 002 把 `favicons` 表整个重建（字节改落盘），旧的图标缓存会丢失并在
  下次访问时重取——它是纯缓存，这是有意的取舍。
- **服务端搜索接口目前前端不再调用**（筛选搬到客户端了），能力与单测都还在。
- `created_at` 存 UTC 时间字符串，界面未展示；回收站里的删除时间按 UTC 显示。
